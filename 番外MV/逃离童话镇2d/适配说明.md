## 二、字体：按片子实际用字现做子集

`fonts.css` 要 4 个字族（MV Brush / MV Cute / MV Hei / MV Serif），每族一个主文件 + 一个拉丁字母补充文件（`unicode-range: U+0000-024F,U+2000-206F`）。

从 npm 取源字体（`@fontsource/*`，都是 Google Fonts 的 OFL 版本）：

| 目标文件 | 源 | 风格 |
|---|---|---|
| `brush0/brush1.woff2` | Ma Shan Zheng 400 | 毛笔手写——片名、字卡 |
| `cute0/cute1.woff2` | ZCOOL KuaiLe 400（仓库自带 `通用模板/engine/assets/fonts/`） | 圆体——活泼标牌 |
| `hei0/hei1.woff2` | ZCOOL QingKe HuangYou 400 | 黑体宣传字 |
| `serif0/serif1.woff2` | Noto Serif SC 400 | 衬线——念白、英文斜体 |

子集用的是**扫源码扫出来的实际字符集**：295 个汉字 + 全 ASCII + 常用标点 = 419 个字符。`pyftsubset --flavor=woff2 --no-hinting` 生成，合计 340 KB（未子集的源文件一个就有 13–86 MB）。

字符集是用脚本从 `src/**/*.ts*` 里所有字符串、`txt('…')` 调用、以及 `App.tsx` 的界面文案里抽的；如果之后加了新词，跑一遍同样的流程补字即可。

## 三、改了工程的两处

只动了「能不能跑」和「能不能出片」，没有动画面内容：

### 1. `vite.config.ts`：放行外部 Host

```ts
server:  { host: true, allowedHosts: true, port: 5288, strictPort: false },
preview: { host: true, allowedHosts: true, port: 5288, strictPort: false },
```

原配置没写 `server`，Vite 默认拒绝非 localhost 的 Host 头，预览域名会被 403 挡住。只影响 dev/preview，`build` 出来的单文件不受影响。

### 2. `src/App.tsx`：加出片模式（`?capture`）

原页面只有交互播放，帧导出工具拿不到干净画面——封面层和控制条会被一起截进去。加了 4 处，全部由 `?capture` 开关控制，正常观看走原路径：

| 位置 | 改动 |
|---|---|
| `const capture = …` | `URLSearchParams(location.search).has('capture')` |
| `showUi` | `(ui \|\| !playing) && !capture`——出片时不出控制条 |
| 封面 / 结束卡 | `{!started && !capture && …}`：出片时不画封面 |
| 初始化分支 | 有 `?capture` 时**只渲染一帧就停**，不启动自己的 `requestAnimationFrame` 循环（否则会把外部 seek 的帧覆盖掉），并暴露 `window.__captureStage = () => wrapRef.current` 告诉抽帧工具「舞台就是 `.mv-stage` 这一层」 |

页面原本就有 `window.__mv.seek(t)` 和 `window.__mv.shots`，出片工具直接可用。

## 五、时间轴与 BGM 的关系（重要）

**工程按 111.5 秒写，BGM 是 212.27 秒**——差近一倍。实测过，两边的分段结构几乎每个界线都吻合（3 / 7 / 13 / 18 / 20 / 24 / 29 / 37 / 42 / 51 / 53 / 58 / 60 / 89 / 93 / 100 / 102 / 104 / 158 s…），所以这份时间轴配这首曲子本身是对的，只是 BGM 在 111.5 秒之后还有约 100 秒没有对应画面。

**决定（本次）：按工程原样出片。** 保持 `END = 111.5`、`FADE_A = 104.2`，成片约 1:51.5，音乐在 104.2 秒起淡出、111.5 秒收尾。BGM 后 100 秒不用。

如果以后要放满 212.27 秒，需要先补 100.9 秒之后的分镜（现在 `OUT` 镜之后没有内容）。

## 六、出片命令与踩到的坑

```sh
# 1) 出片（111.5 秒 × 30 fps = 3345 帧，1280×720）
node tools/shoot_vite_mv.mjs --dist 番外MV/逃离童话镇2d/dist \
  --out /tmp/etz2d_frames --dur 111.5 --fps 30 --w 1280 --h 720 \
  --format png --query capture

# 2) 编码（h264 crf21 + aac 192k，与仓库惯例一致）
.venv/bin/python tools/encode_frames.py --frames /tmp/etz2d_frames \
  --audio 番外MV/逃离童话镇2d/src/assets/song.mp3 \
  --out 番外MV/逃离童话镇2d/成片/逃离童话镇2d.mp4 \
  --crf 21 --maxrate 3200k --afade-out 104.2:7.3
```

**`--afade-out` 是这次给 `tools/encode_frames.py` 新加的**：页面里的音乐淡出是用 `audio.volume` 做的，导出静帧再编码时那段代码不参与，必须在这一侧补 `afade`。起点 104.2、时长 7.3 秒，正好到 `END = 111.5` 淡完。

### 坑一：CSS 的 film grain 让每帧多花 25 秒

第一次按原样跑，**每帧 25–34 秒**，3345 帧要 18 小时以上。测下来瓶颈全在截图上：

| 情况 | 每帧耗时 |
|---|---|
| `page.screenshot`（原样） | 25.79 s |
| `canvas.toDataURL`（绕开 DOM 叠层） | 15.71 s |
| **`page.screenshot` + 关掉 `.mv-grain`** | **0.49 s** |
| 再关掉 `.mv-vignette` | 0.30 s |

元凶是 `.mv-grain`：`mix-blend-mode: overlay` + SVG `feTurbulence` 滤镜 + `inset: -20%`（比画面大 140%）+ 0.7 秒步进动画的 `steps()`。软件渲染（SwiftShader）下这一层每帧都要重新栅格化整块混合层，比整个 three.js 场景还贵。

**处理**：用工具自带的 `--hide ".mv-grain"` 摘掉它，出片后由 ffmpeg 的 `noise` 补回。实测原 grain 只有 `opacity: .09`，和干净帧的平均绝对差只有 **1.05**（肉眼几乎看不出），对应 `noise=alls=4`（差 1.26），所以用 `--grain 4` 补。最终 3345 帧耗时 **约 12 分钟**，4.5 帧/秒。

### 坑二：`--still/--from/--to` 会清空 `--out` 目录

老规矩了：分段渲染时不要指望上一次的帧还在。
