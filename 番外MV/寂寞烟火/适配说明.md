# 寂寞烟火 · 上传工程还原与出片记录（2026-11-25）

用户上传 `寂寞烟火.zip`（2.0 MB，React + Vite + three.js 的 3D 像素微缩（voxel-diorama）MV 工程），要求「解压渲染视频并且给出文案推送分支」。
包内**只有源码 + 两张像素图 + 一个 Blender 生成脚本**：11 个 `.glb` 场景模型和整条音轨都不在包里，`index.html` 还挂着 Google Fonts 外链。下面记清楚缺什么、怎么补的、源码动过哪几行。

## 三、源码上动过的几处（都是为了「能离线逐帧出片」）

1. **`?capture` 出片模式**（`src/App.tsx`）：读 `location.search` 里的 `capture`，为真时
   - `started` 初值为真（原本要等用户点播放才出字幕）；
   - 字幕透明度锁 1（原本 63.3 s 后淡出）；
   - 不渲染封面层（标题 + 播放按钮）与结尾「重新播放」层；
   - 画面容器改成 `100vw × 100vh` 铺满、去圆角/边框内距，控制条 `hidden`。
   正常访问（不带参数）行为一字未变。
2. **`window.__captureStage`**（同文件）：出片时告诉截图脚本「整页舞台 = `#mv-cinema-frame`」，
   也就是 **3D 视口 + 内嵌字幕条这一层**。原工程的字幕是 DOM 兄弟节点，若不指定，截图工具只会拍 canvas 父元素，字幕条会被挤出画面。
3. **`index.html` 去掉 Google Fonts 外链**、`src/index.css` 引入本地 Noto Sans SC 子集（见上表）。

## 四、出片

```sh
# 0) （只需一次）生成 11 个 Blender GLB —— 沙盒里用 pip 版 bpy 代替 blender 可执行文件
python3 -m venv /tmp/blenv && /tmp/blenv/bin/pip install bpy==4.2.0
#   注：bpy 依赖 libXrender/libXi/libxkbcommon 等 X11 库，沙盒里一个都没有；
#   用一组符号桩（只导出符号、不实现）在 LD_LIBRARY_PATH 里顶上即可跑 headless，
#   不参与渲染、不影响几何输出。
cd 番外MV/寂寞烟火/源码 && LD_LIBRARY_PATH=<桩目录> /tmp/blenv/bin/python -c \
  "import runpy,sys; sys.argv=['blender','-b','-P','scripts/generate_blender_assets.py']; runpy.run_path('scripts/generate_blender_assets.py', run_name='__main__')"

# 1) 构建（单文件 dist，图集 / GLB / 字体 base64 内联，约 10.5 MB）
cd 番外MV/寂寞烟火/源码 && npm install && npx vite build

# 2) 逐帧（页面是 __mv.seek 路径 → 整页截图，DOM 字幕与闪光会一起进画面）
node tools/shoot_vite_mv.mjs --dist 番外MV/寂寞烟火/源码/dist \
  --out /tmp/jm_frames --dur 65.09 --fps 30 --w 1280 --h 720 --format png --query capture

# 3) 编码 + 混音
python3 tools/encode_frames.py --frames /tmp/jm_frames \
  --audio 番外MV/寂寞烟火/源码/src/assets/jimo-yanhuo.mp3 \
  --out 番外MV/寂寞烟火/成片/寂寞烟火.mp4 --fps 30 --crf 21 --maxrate 3200k
```

- 出片规格：1280×720 @30fps，h264（crf 21 + VBV 3200k）+ aac 192k 立体声。
- 沙盒 2 核无 GPU（SwiftShader 软光栅 + bloom 合成），实测约 **1.5 帧/秒**，1953 帧约 22 分钟。

## 五、共用工具的两处改动

`tools/shoot_vite_mv.mjs` 与 `tools/capture_quality.mjs` 的 seek 分支原来都写死「舞台 = 最大 canvas 的父元素」，并且把 canvas 拉满视口。
对《寂寞烟火》这种「canvas + 内嵌 DOM 字幕条」的结构，会把字幕条整个盖住。现在两处都改成：
页面若导出 `window.__captureStage()` 就用它当舞台，**且不再改动 canvas 的尺寸**；没有该钩子的工程行为完全不变。
