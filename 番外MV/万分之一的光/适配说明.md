## 三、源码上动过的几处（都是为了「能离线逐帧出片」）

1. **`window.__mv` 出片钩子**（`src/mv/Player.tsx`）：原工程只给页面内的播放器用，没有外部时间钩子。
   新增一个 `useEffect` 把 `{ ready, width, height, dur, render(t, _noLyric, width) }` 挂到 `window.__mv`；
   `render()` 把画布固定成 1280×720、调 `renderFrame(c, t, { sub: true })` 重画一帧后返回 `true`。
   页面本身的播放、进度条、全屏、快捷键行为不变。
2. **出片时收起叠层**（同文件）：`render()` 首次调用会把封面卡 / 播放按钮 / 底部控制条藏掉（`capture` 状态），只留画布本体。
   原工程封面卡是 `(!started || ended)` 条件渲染的，若不收起，截出来的每一帧都盖着「点击播放」。
3. **同步开关 `captureRef`**（同文件）：页面自己那条 `requestAnimationFrame` 循环读的是音轨时间，
   第一次排查时它把刚渲好的帧又覆写回封面帧（9.6 s），导致 t=24/70/120/200 四张截图**逐像素完全相同**（差 0.00）。
   现在 `render()` 一进来就把 `captureRef` 置真，循环立刻 `return`，画面只由外部时间决定。
   `shoot_vite_mv.mjs` 的 `freezePageLoop()` 只冻首次 `requestAnimationFrame`，挡不住后来重新注册的循环，所以这一步必须在页面里做。

## 四、出片

```sh
# 1) 构建（单文件 dist，图集与字体 base64 内联，约 9 MB）
cd 番外MV/万分之一的光/源码 && npm install && npx vite build

# 2) 逐帧（tools/shoot_vite_mv.mjs 自动选中 __mv.render 路径；PNG 无损）
node tools/shoot_vite_mv.mjs --dist 番外MV/万分之一的光/源码/dist \
  --out /tmp/wfy_frames --dur 226.64 --fps 30 --w 1280 --h 720 --format png

# 3) 编码 + 混音
python3 tools/encode_frames.py --frames /tmp/wfy_frames \
  --audio 番外MV/万分之一的光/源码/src/assets/bgm.mp3 \
  --out 番外MV/万分之一的光/成片/万分之一的光.mp4 --fps 30 --crf 21 --maxrate 3200k
```

- 出片规格：1280×720 @30fps，h264（crf 21 + VBV 3200k）+ aac 192k 立体声。
- 沙盒只有 2 核 / 3 GB、无 GPU，纯软件光栅实测约 **2.2 帧/秒**，6799 帧约 50 分钟。
