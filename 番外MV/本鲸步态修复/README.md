# 本鲸步态修复：前后对照

2026-11-13 修掉了本鲸（`walk_whale_0–7`）走路时裙摆前方那条多出来的鱼尾。这里是修完留下的对照材料，
按用户要求入库（`*.mp4` 默认不入库，这两支是例外，校验值同时记在 [`媒体说明.md`](../../媒体说明.md)）。

## 出了什么问题

八帧步态存在 `通用模板/cast/source/walk_cycle_data.js`，由旧工程脚本按 **90 px 定距切条带**生成（生成脚本不在本仓库）。
切格时把隔壁那一个实例的边角一起切了进来：

- 裙摆**右前方**一片淡蓝尾鳍，与身体没有连接——观众看到的就是「行走时前面多出的那条鱼尾」，八帧里六帧有；
- 右下角还带进另一只靴子的边沿（同样越界）。

不是渲染、不是图集坐标的问题：从图集里直接切出来的八格、和你截图里的画面逐像素对得上。

## 怎么修的

`tools/fix_whale_walk_bleed.mjs` 只做减法，把越界像素置 255（透明）：

| 区域 | 范围 | 清掉的是 |
|---|---|---|
| E1 | `x ≥ 66`，`y 60–76` | 那条尾鳍 |
| E2 | `x ≥ 69`，`y 77–88` | 隔壁的靴沿 |
| — | `x 64–65`，`y 64–70` | 与裙摆粘连的残渣（干净帧这一段本来就空） |

八帧共清掉 **425 个像素**（第 7 帧本来就干净，0 个）。身后那条真正的鲸尾、裙摆、手脚一个像素没动。
复验：`node tools/fix_whale_walk_bleed.mjs --check`；改完照例 `npm run atlas`（`npm run atlas:check` 逐字节校验）。

图集仍是 **2048×3126 · 682 格，坐标一格没动**，只换了这八格的像素：
`sha256 5f9894b6ad38c26a62ec55a030aeb49bce8360c3d67ef99d1f581430d7ec81da`。
