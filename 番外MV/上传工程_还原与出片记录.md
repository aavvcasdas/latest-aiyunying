## 三、源码上动过的几处（都是为了「能离线逐帧出片」）

1. **图集坐标重映射**（情歌两版）：两个包里的 `src/mv/generated.ts` 存的是**它们自己那份重排图集**的坐标——
   帧名、帧尺寸与母版完全一致，但 `x/y` 501 处全不同，直接配母版图集会裁错（画面里会出现半截立绘）。
   已按名字把 `RECTS` 全量换成母版 `cast_atlas.json` 的坐标，并把 `ATLAS_H` 从 4096 改成母版真实高度 3126。
2. **`__mv.render(t, noLyric, width)`**（情歌 opus5.5max）：原版没有 `width` 参数，`toDataURL` 只能拿到页面尺寸（1420×798）。
   加了一个可选宽度：传 1280 时先 `eng.setSize(1280, 720)` 再渲，出片分辨率因此固定。
3. **`window.__seek`**（我好想你mv）：这个工程只有页面内的播放控件，没有给外部留时间钩子。
   在 `seekTo` 后面加了一个 `useEffect` 把 `seekTo` 挂到 `window.__seek`（页面本身行为不变），出片脚本按帧调用。
   另外它自带的 `?clean` 参数会隐藏开场卡与控制条，出片时用 `?clean`。

## 四、出片

```sh
# 1) 构建（三个工程各自）
cd 番外MV/<工程>/源码 && npm ci && npx vite build      # 产出 dist/index.html（单文件，图集与字体内联）

# 2) 逐帧（tools/shoot_vite_mv.mjs：自动选 __mv.render 或 __seek + 整页截图）
node tools/shoot_vite_mv.mjs --dist 番外MV/情歌_opus5.5max/源码/dist --out /tmp/frames_qg --dur 261.5 --w 1280 --h 720
node tools/shoot_vite_mv.mjs --dist 番外MV/情歌_opus5.5max-gpt6max开头/源码/dist --out /tmp/frames_qg6 --dur 261.5 --w 1280 --h 720
node tools/shoot_vite_mv.mjs --dist 番外MV/我好想你mv/源码/dist --out /tmp/frames_whx --dur 329.33 --query clean --w 1280 --h 720

# 3) 编码 + 混音（音轨直接取 素材/ 里那份，不重采样）
```

- 出片规格：1280×720 @30fps，h264（crf 21 + VBV 上限）+ aac 192k 立体声。
- 为什么不是 1080p：沙盒只有 2 核、3 GB 内存，没有 GPU，`UnrealBloomPass` 全靠软件光栅；
  实测同一帧 1280×720 约 0.43 秒、1920×1080 约 0.94 秒。三个包合计 25,570 帧，
  720p 已经是能在一次会话里跑完的上限。**要 1080p 直接改 `--w 1920 --h 1080` 重跑，机器快就行。**

## 六、检查到的问题

- 三个包都**没有** `public/` 与 `src/assets/` 里的二进制，说明导出时是按源码目录打包的；
  以后要交接可直接出片，得把 `src/assets/` 一起带走。
- 《我好想你》的 `cast.json` 与母版图集帧名、帧尺寸 196/196 全对得上，只是重排过布局——
  这说明它的精灵图是母版图集的子集重排，**不是新画的角色**，补图集合规。

## 七、出片时踩到的三件事（下一支片子照这个来）

1. **图集坐标不能想当然**：两个《情歌》包的 `RECTS` 与母版图集「帧名、帧尺寸全同、坐标全不同」。
   直接配母版会裁到隔壁帧（画面里出现半截立绘和两块拼在一起的图），必须按名字重排坐标。
2. **gpt6max 开场版的 `capture()` 每帧渲两遍**（`engine.render(t, clean, cover)` 连着写了两行）。
   实测两次输出**逐像素完全一致**（t=6 / 61.5 / 195 三帧差值均为 0），删掉一行后速度从 0.93 fps 提到 1.6–1.7 fps。
3. **《我好想你》的颗粒层太贵**：`.grain` 是 `feTurbulence` + `mix-blend-mode: multiply` 的全屏叠层，
   每帧截图从 385 ms 涨到 845 ms。出片时用 `--hide .grain` 摘掉，再用 `encode_frames.py --grain 8` 在编码阶段补回颗粒
   （暗角 `.vignette` 是渐变，留着不贵）。
