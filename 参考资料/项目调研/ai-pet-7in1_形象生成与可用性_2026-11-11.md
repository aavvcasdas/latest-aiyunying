## 二、形象是怎么生成出来的

不是画出来的，也不只是"AI 一键生成"，是**三步流水线**：

**1）定参考**：用社区现成的 chibi 参考图（AI-Fanworks 的 `<角色>-Chibi.png`）当"这份形象长什么样"的唯一依据。`CODEX-PROMPTS.md` 里写明：把角色换成 claude / gemini / glm / kimi / grok，参考图对应同名文件。

**2）生三张关键帧**（Codex 内置图像生成，一次一张，`design/<角色>/`）：

| 关键帧 | 提示词要点 |
| --- | --- |
| `idle.png` 定稿形象 | 忠实重画参考图的 chibi（同脸、同发、同配饰、同 logo 装饰、同衣、同翼尾）；只改成**正面站姿、双手自然垂在身前、无道具、无特效、全身露脚、居中**；画布 **576×1024**；**纯绿 #00FF00 平背景**，无影无字 |
| `walk.png` 左走 | 以上一张为"角色模型表"，生成**侧视、朝画面左侧、迈步中**，表情开心，同画布同比例，脚落在同一底边，纯绿背景、无影无地无字 |
| `drag.png` 被拎起 | 同角色被"看不见的手"从后领拎起：正面、脚悬空、四肢张开、惊讶加汗滴，纯绿背景、**不画手** |

**3）抠像 + 对齐 + 导出**（`tools/key_to_webm.py`，本仓库里能直接读到的算法）：
- 解码绿幕视频 → 按 **24fps** 重采样；
- alpha 用 **`g − max(r,b)`** 软阈值两段线性（lo=18 / hi=70），再做绿色溢色抑制 `g = min(g, max(r,b)+4)`；
- 有 `key_protect()`：只把"接近纯绿幕色"的像素当背景，内部绿色道具（叶子、光环）保留，背景边缘 2px 内仍走普通抠像；
- 统一画布 **640×360**（或 ×2 的 1280×720），**人物脚底线 y=329、水平居中 x=320**，和上游 DeepSeek 娘素材同一布局；
- 首帧 bbox 还能 `--match` 对齐到旧素材，保证换代不跳位；
- 补间与动画本体不在这个仓库里（README 只写"关键帧用 Codex 出图，再做成动画并抠图"），推测在外部的动画工具里完成，仓库只留成品 webm。

**结论：形象 = AI 生成的关键帧（绿幕、576×1024、同一张参考图锁形象）＋ 程序化抠像对齐 ＋ 外部的补间导出。** 它的可取之处不在"生成得像"，而在于**用一张参考图锁死形象、绿幕统一抠像、所有动画共用同一条脚底线**——这三件事正好是我们做纸片人最需要的。

## 三、规格（要接进别人的片子，就得按这个来）

| 项 | 值 |
| --- | --- |
| 容器 / 编码 | webm / VP9 + alpha |
| 分辨率 | 640×360（GPT 另有一份 1280×720），16:9 |
| 帧率 | 24fps |
| 人物定位 | 脚底 y=329（720p 版 y=658），水平居中 x=320（720p 版 x=640） |
| 命名与状态 | 中文动作名；固定状态：`待机` `登场` `走路` `点击回应-*` `被鼠标拖拽悬空反馈` `工作状态-*` `余额-*` `碎碎念-*` `专属-*`，其余为日常小动作 |

## 四、能不能直接拿来做我们的视频

**技术上能，实际上不行。** 分两栏说清楚：

| 技术上 | 结论 |
| --- | --- |
| 透明 webm 能不能叠进 Remotion | 能。Chromium 认 VP9 alpha，`<Video>` 逐帧 seek 是确定性的 |
| 尺寸够不够 | **不够**。640×360 里人物约占 250px 高，铺到 1080p 是 3 倍放大；它本来是桌面上的小挂件，不是给 1080p 特写的 |
| 画风 | **冲突**。它是柔和阴影的 AI chibi；我们整条线是同一套像素图集（`通用模板/cast/source/`），两者同框就是两种画风 |
| 与我们的红线 | 直接冲突：`AGENTS.md` 写着「不新增生图、不换画风；角色只用图集里的像素造型」 |

| 法务上 | 结论 |
| --- | --- |
| 素材许可 | **CC BY-NC-SA 4.0：非商业 + 相同方式共享**。卖、收费分发、广告变现都不行 |
| DeepSeek 娘 | 上游另外声明「禁止商用」，并要附上游地址 |
| 传染性 | SA 要求二创同协议——要把素材放进我们的片子，等于整个仓库跟着换协议 |
| 署名 | 必须同时署 ZipZipPipe、ApprenTice、上善无形、PC2005-cloud 四处 |

**所以：不把它的画面搬进任何成片。** 不是"技术上做不到"，是"这么做会把整条产线的许可和画风一起拖下水"。

## 五、那能借什么（已经借了两样）

1. **工作流**：一张参考图锁形象 → 绿幕关键帧（idle / 走 / 被拎起三视图）→ 统一抠像 → 统一脚底线 → 批量导出。这套做法和我们的像素图集不冲突，将来真要加新角色造型可以照它走。
2. **动作词表**：112 个动作名 + 状态分组，是一份现成的"角色能干什么"清单。**名字可以借，画面不借**——已整理进 [`设定/动作库.md`](../../设定/动作库.md)，标了我们用现有造型格能演哪些、哪些必须新做。
3. **许可写法**：`LICENSE-ASSETS.md` + `NOTICE.md` 分开写代码与素材、逐项列来源与许可，这个格式可以照搬。已落成 [`素材许可与来源.md`](../../素材许可与来源.md)。
