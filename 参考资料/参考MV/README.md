# 参考 MV：谁跟谁并列、谁排其次

**2026-11-12 定。** 以后做番外 MV，参照物按这张表排：**《反乌托邦》与《童话镇》并列第一**，**《坏女孩》其次**。

## 1. 现在的排位

| 档 | 作品 | 在哪 | 是什么 | 拿来当什么 |
| --- | --- | --- | --- | --- |
| **第一梯队（并列）** | 《反乌托邦》 | [`反乌托邦/`](反乌托邦/) | 113.38 秒 · 121.99 BPM · 1280×720 @30fps · 60 镜 · 58 条歌词时间戳 · Canvas2D 软 3D（画家算法，同一套九位角色图集） | **时间纪律**：词轴怎么测、切点挂在哪；**把一首歌重新讲成一个童话**的改写法 |
| **第一梯队（并列）** | 《童话镇》 | [`../../番外MV/童话镇/`](../../番外MV/童话镇/) | 142.4 秒 · 40 镜 · 31 句歌词 · three.js 立体童话书 · 4272 帧（2 分 22 秒） | **画面语言**：书页、纸艺、翻页、剪影；也是现行模板（`通用模板/`）的来处 |
| **第二梯队（其次）** | 《坏女孩》（3D 版 / Fable 版） | [`../../番外MV/坏女孩/`](../../番外MV/坏女孩/)、[`../../番外MV/坏女孩Fable/`](../../番外MV/坏女孩Fable/) | 3 分 17 秒 / 195 秒，同一首歌的两版实现：three.js 夜雨、Canvas2D 软 3D | **引擎源头**（软 3D 那套 `render(ctx, t)` 是纯函数）＋ 夜戏、雨、情歌的打法 |

「并列」不是客气话，是四条具体做法：

1. **排期上不分先后**：下一部片子开工，两支都要先看一遍；哪一支更贴这首歌，就用哪一支当母版。
2. **有冲突时按歌定，不按片子定。** 例如《童话镇》基本一句词一个镜头，《反乌托邦》遇到长句会在句内再切一刀（切点 = 这句起点 − 2 帧）。两种都成立，选哪个看这句词压不压得住一个镜头。
3. **引用要写清是哪一支**：写「照反乌托邦那种句内切」，不要写「照参考 MV 那样」。
4. **两支都不许整段照搬**：那两支的分镜是给那两首歌排的，镜头顺序、布景坐标、机位数值搬过来就是错的。

## 2. 《反乌托邦》这一支，值得抄什么

源码就在 [`反乌托邦/`](反乌托邦/)（出处见第 4 节）。**这份源码在本仓库里没有装依赖、也没有跑过**：`npm install` 要另装 react + vite 一整套，而它出片靠的是 `/tmp/tools` 里的 `@napi-rs/canvas` 和 ffmpeg-static（见 `scripts/render-mp4.mjs` 开头）。拿它读做法、抄公式，别指望在仓库里一条命令出片——我们自己的片走 `通用模板/`。

| 看哪里 | 里面是什么 | 为什么值得抄 |
| --- | --- | --- |
| `src/mv/lyrics.ts` | 58 条歌词时间戳，4 条是两句并成一条字幕 | 时间不是估的：把原 MV 每 0.5 秒抽一帧，看每句第一个字出现在画面上，再吸附到实测拍点上。用户给的时间戳整体早了 0.5–1 秒、0:52–1:19 那段没时间戳，都补齐了。**「实测 + 吸附拍点 + 补缺」这套流程正是我们的 `align` 在干的事**，两边可以互相校 |
| `src/mv/shots.ts` | 60 个镜头，一镜一句词 | 切点写成「这句起点 − 2 帧」；镜内的时机全挂在词上（词首 / 每个字唱到的时刻），**没有一处写「镜头的百分之几」**——和我们「时机挂在句子上」是同一条纪律 |
| `src/mv/core.ts` | 软 3D 引擎核心（面片、画家算法排序、雾、倒影） | 同一个 `t` 永远画出同一帧，网页预览和逐帧导出走同一份 `render()`；缺布景直接抛错（`getSet` 不认识就报，不拿别的顶替） |
| `src/mv/fairy.ts`、`src/mv/fx.ts` | 一批童话道具画法：带翅膀的心、露水网、小刀、折纸船、孔明灯、八音盒齿轮、相片铺地、停摆的钟 | **只借画法，不借坐标**：道具怎么用几层多边形拼出来、怎么抖、怎么亮，是可以学的 |
| `scripts/render-mp4.mjs` | Node 侧逐帧调 `render()`，管道喂 ffmpeg | 音轨 `-c:a copy` 直接从原曲拷，保留编码器预滚，做到逐采样对齐——我们混音时「按采样对齐」也是这个道理 |
| `src/mv/beat.ts`、`src/App.tsx` | 实测 BPM 与包络表；网页里几页「歌词校对 / 卡点怎么来的 / 这一版怎么理解歌词」 | 把「我们为什么这么切」写进片子旁边，比写在文档里更容易被下一部片子继承 |

**别借的：**

- 它的选角——那一支直接套用了《童话镇》的设定表（鲸鱼娘主角、智谱演彼得潘……），我们的人怎么派形象以 [`../../设定/README.md`](../../设定/README.md) 和 [`../../番外MV/设定表.md`](../../番外MV/设定表.md) 为准。
- 它的 60 镜顺序、布景坐标、机位数值。
- `src/mv/assets/song.ts` 里那段音频（是这首歌本身）：**不许**当我们的音源用，也不许出现在我们的成片里。
- 它的片头卡与字幕条样式：我们的规矩是零水印、片头只留歌名与歌手名。

## 3. 《坏女孩》为什么排第二

1. **它是引擎的源头，不是画面语言的母版。** 现行模板的软 3D 画家算法、按位移迈步的 `walkBy()`（一轮 1.15 × 缩放）都是在这支里改出来的；但它给出的是一套算法，不是一套讲故事的办法。
2. **同一首歌两个版本，看的是实现，不是分镜。** 3D 夜雨版和 Fable 版镜头不同、帧率不同（30 / 24 fps），拿它当「照抄对象」会照出两份互相矛盾的分镜。
3. **感情戏只在那一支里成立。** 本鲸和小克在那支里是剧情，不是正史 CP（见 `番外MV/设定表.md` 的硬规矩）。

要用它的时候，取这几样：夜戏的雨与霓虹怎么分层、情歌怎么给两位歌手分配镜头、以及「引擎是纯函数」这件事本身。

## 5. 一句话

**参考是拿来定做法和取舍的，不是拿来当分镜抄的。** 两支并列的意思就是：下一次坐在桌前写 `shots/`，桌面上该同时摆着《反乌托邦》的时间表和《童话镇》的书页。
