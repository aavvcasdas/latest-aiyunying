# 人物/q版HD_2x —— 八位角色的 2 倍高清素材（去白边）＋ SVG

> 2026-11-21。这一包是 fix.zip / fix2.zip（八位 Q 版的高清图包）**在仓库里落地并优化过**的版本。
> 原图集（`人物/atlas.png`、`通用模板/engine/assets/cast_atlas.*`）一个字节没改：旧片重渲还是逐帧一样。

## 2026-11-21 补：换成 fix 包的真 4 倍超分底（先只做本鲸）

之前那版 2 倍是**整数放大**：高清图集里每格是 2×2 完全相同的像素块（实测 2×2 块 100% 一致），
所以画面上的「高清」只是方块更大，边缘依旧是柔的——你的观感「和之前一样模糊」是对的。

`fix.zip` / `fix2.zip`（两个包解压后逐字节相同）里带的是 **108 张基础格的 4 倍 Real-ESRGAN 超分版**，
是真细节（蕾丝、发丝、眼睛高光、围裙上的鲸鱼刺绣）。现在按 2 倍口径把它们降采样入库：

```bash
npm run cast:hd:fix                                        # 108 张基础格全部换成包里的 4 倍底（约 20 秒）
npm run cast:hd -- --only whale                                         # 重新派生 16 个动作
npm run cast:hd:atlas                                                   # 重烘图集
```

- 4 倍图先 LANCZOS 降到 2 倍，再对 RGB 做一次轻反锐化（radius 1.1 / 115%），**alpha 不动**（动了会出黑边）。
- 尺寸与 `index.json` 记的 2 倍尺寸逐张对得上（108 张全对上），所以派生动作、图集烘焙、引擎坐标都不用改。
- 八位全部换完后图集从 16.0 MB → **25.3 MB**（6144×3706，682 格）。

引擎侧同时改了两处（`通用模板/engine/actors.ts` 的 `pixelMat`）：

1. **有高清层时不再把取样点吸到 1 倍格心**。以前是先吸附再乘倍数——对整数放大是对的，但对有真实细节的超分图，
   等于把亚像素细节全抹平，退回方块。现在只有 1 倍层保留像素画吸附。
2. **高清层做 4 邻域反锐化 + alpha 收紧**（`SHARPEN 1.5`，`smoothstep(0.45, 0.62)` 收轮廓）。超分图是抗锯齿的，
   采样到屏幕上会再糊一层，不收就是一圈灰边。

对比数据（同一帧 f200、同为 1920 宽，角色区域梯度均值）：旧 4.82 → 新 **6.44**（+34%），轮廓可见地硬了。
逐帧渲染没有变慢（3.7 帧/秒，和之前一样）。

八位全部换完了（`--only` 不写就是全量）：

```bash
npm run cast:hd:fix                                       # 108 张基础格，约 20 秒
npm run cast:hd                                          # 重新派生 1470 帧，约 30 秒
npm run cast:hd:atlas                                     # 重烘图集，约 10 秒
```

## 顺手修掉的两个「人物被裁一半」的 bug

动作总览里的「GPT 龙娘 · 振翅悬停」那一帧只剩躯干和腿，原因是两处：

1. **HD 的 `hover` 用错了基础格**：HD 侧用的是站姿大格（`gpt_boss_idle`，264×352），而引擎里这一格的画框是按 1 倍的振翅小格（75×104）算的，
   大格塞进小画框只剩中间一截。改成振翅格（`gpt_fly_*`）+ 轻微上下浮动，和 1 倍层对齐。
2. **`hop` 的起跳方向反了**：HD 那段 sy 只在 0.93–1.05 之间抖、dy 最多 -9，看起来像原地压扁；1 倍是「先蹲一下再往上跳离地」。
   现在 dy 到 -18、蹲下时 sy 0.92，起跳幅度和 1 倍一致。

另外把图集烘焙的派生格对齐改回「格底中点 + 脚底锚点」：派生格的画布是这位角色最大的那一格，画框比 1 倍格大，
只按画框中心裁会整格偏几十像素。现在 `act_*` 的内容外框和 1 倍层的误差在 2 像素以内（逐格量过 492 格：10 格因为起跳离地本来就是位移，其余全部对上）。

## 白边：量在哪、怎么去

原图集的 alpha 只有 0 / 255 两档，透明处 RGB 是纯黑——所以片子里的白边不是渲染插值带出来的，而是**抠图残留**：每格最外圈是烘焙时加的 1 像素墨线 `#181425`，残留的浅色像素夹在**墨线内侧那一圈**。

规则只动「比里面亮、朝白偏、往里 3 圈内又找不到相近颜色」的像素，把它重上色成里面的颜色；真的浅色细节（蕾丝、围裙、手、浅色发梢）有 ≥2 像素厚，会被认作「有支撑」、不动。轮廓和墨线一个像素都不改。

- 108 张基础格：残留 **889 → 16 像素**（`python3 通用模板/cast/hd/hd_base.py --report`）。
- 走路帧原来**没有**墨线（站立切走路时描边会消失），这一版补上（格子四边各多 1 像素）。
- 片子里还可能看到的白来自 bloom / 色差（根目录 README 写过）。那一层没有动，也没有渲整片复测。

## 「高清格和 1 倍格来回切」：46 格缺口，补了 32 格

引擎的动作表（`通用模板/engine/assets/cast_actions.json`）和高清动作库（`通用模板/cast/hd/motion_hd.mjs`）来自两份不同的脚本，各缺对方几个动作。对得上的是 492 格，**46 格高清图集里原来是空的**——引擎对着空 rect 退回 1 倍那一层，同一个动作里高清格和 1 倍格来回切，人物忽清忽糊（镜头里看就是「一半帧清楚、一半帧糊」）。

`npm run cast:hd:patch` 补了能补的：

| 动作 | 格数 | 怎么办 |
| --- | ---: | --- |
| whale/spin、doubao/spin、gemini/spin、qwen/spin | 32 | 按高清库的 `turn` 重派生：正面 / 侧身 / 镜像换格转身，不再像 1 倍那版把人横向压成 0.34 的细条 |
| whale/eat（8 格）、claude/petri（6 格） | 14 | **没补**：高清库没有这两个姿态（eat 要「低头扒饭」的基础格，petri 要石化色），硬拿别的动作顶会换造型，这几格继续用 1 倍 |

补完高清图集 600 → 632 格（682 格里剩下的 50 格是道具 / 表情贴和这两条动作，高清包按设计不派生）。

## 还没接上的：SVG 的「对齐」

`svg/<角色>.json` 里每格的 rect 是**在 SVG 自己的画布上的坐标**（格宽统一、按最大宽高排成一列），
不是 1 倍图集里的 rect。拿它去替换引擎的取样会很省事，但那样一来高清格和 1 倍格的**底边中点就对不上了**，
人物会在换格的一瞬间横移 / 跳一下（腿长、尾巴宽窄每格都不一样）。

所以现在引擎接的是**高清图集**（`cast_hd_atlas.*`，每格都是「1 倍 rect × 2」、底边中点对齐，所以摆位不用改），
SVG 只当素材 / 预览 / 矢量输出。要把 SVG 接进成片，得先在 `svg_pack.mjs` 里把每格按「底边中点 = 1 倍 rect 的底边中点」
重新落位、再按 1 倍 rect 的尺寸补齐画布，然后 SVG 光栅化的那张贴图才能顶替 `cast_hd_atlas.png`。这一步没做。

## SVG：体积怎么降下来的

`人物/q版HD_2x/svg/whale.svg` 是把 19 张基础格排成一列的一个文件：

- **每色一条 `<path>`**，路径里只有数字；同色的相邻像素方块合并成矩形轮廓，1 像素高的段写成 `stroke` 横线（`M x .5 h长`），比一个 1 高的矩形少一半字节。
- 同一行里两段同色之间只隔 ≤2 像素的（发丝高光、衣褶），并成一段，缝隙由后画的段盖住——肉眼一样。
- 透明像素**不写**（不会把黑底 / 白底一起复刻过来），半透明写 `fill-opacity`。
- 转换前先跑去残留（和 `hd_base.py` 同一套规则）。whale 19 格去掉 187 个残留像素，其余 7 位 57–331 个。

体积（105 格 4.2 MB；对照：同样的像素用 PNG 是 1.6 MB，同分辨率位图转成 data-URI 塞进 SVG 会更大）：

| 角色 | 格数 | 颜色 | 矩形 | SVG |
| --- | ---: | ---: | ---: | ---: |
| whale | 19 | 450 | 61.7k | 1.04 MB |
| gpt | 7 | 301 | 54.9k | 0.88 MB |
| claude | 15 | 396 | 38.0k | 0.62 MB |
| gemini | 13 | 497 | 28.6k | 0.48 MB |
| zai | 13 | 517 | 30.3k | 0.50 MB |
| kimi | 13 | 343 | 18.9k | 0.31 MB |
| qwen | 13 | 398 | 18.1k | 0.31 MB |
| doubao | 12 | 164 | 10.9k | 0.18 MB |
| **合计** | **105** | — | **261k** | **4.23 MB** |

**会不会拖慢渲染**（实测，同一台机器、同一帧 `番外MV/人物动作总览` 第 400 帧）：

| 这一格怎么画 | 整片连渲 241 帧（400–640） | 一次取静帧（含浏览器启动） | 会不会进成片 |
| --- | ---: | ---: | --- |
| 1 倍图集（老做法） | **67 s**（0.278 s/帧） | 1.44 s | 会 |
| 2 倍高清图集（现在） | **66 s**（0.274 s/帧） | 1.95 s | 会 |
| SVG 光栅化（resvg，角色只占 624 宽） | — | +16 ms/帧 | 不会（实验数值） |
| SVG 光栅化（按 1920 宽整张） | — | +113 ms/帧 | 不会 |

**连渲 241 帧两档只差 1 秒（在噪声里）**：高清图集在第一帧解码一次（那 0.5 s 就是静帧那一列的差），之后每帧只是纹理取样，不按文件大小收费。整片 4772 帧用高清跑下来 1283 s（约 3.7 帧/秒）。

结论：**SVG 不是慢在文件体积上，是慢在「每一帧都要把几万条路径重新光栅化一次」。** 文件大不大几乎不影响渲染速度（图集只在第一帧解码一次）；路径数 × 帧数才影响。所以：

- 成片走**高清图集**这条路（一次解码，之后每帧只是纹理取样）。
- SVG 是**素材 / 预览 / 矢量输出**用的，不进逐帧渲染管线。
- 真要给 SVG 提速：减格数（一个动作一帧一张，别整条带）、`merge` 调大（`svg_px.mjs` 里的并段阈值）、或者把 SVG 交给浏览器当 `<img>` 缓存（浏览器会缓存光栅化结果，但要占显存）。

## 怎么重新生成

```bash
npm run cast:hd:base        # 1 倍图集 → 去残留 + 补墨线 + 2 倍 → 人物/q版HD_2x/base（要 numpy pillow，约 12 秒）
npm run cast:hd             # 高清基础格 → 每个动作一张网格图 + index.json（约 25 秒）
npm run cast:hd:patch       # 补「引擎有、高清包没派生」的那些格（spin ×4），重烘图集（约 8 秒）
npm run cast:hd:atlas       # 682 格装进一张高清图集（引擎的细节层，约 10 秒）
npm run cast:hd:atlas -- --psnr   # 顺便量一下拼图有没有丢像素
npm run cast:hd:check       # 核对 index.json 与磁盘上的图
npm run cast:hd:atlas:check # 核对高清图集与素材
node 通用模板/cast/hd/svg_pack.mjs             # 基础格 → SVG（约 2 秒）
node 通用模板/cast/hd/svg_px.mjs in.png out.svg --scale 4   # 单张图转 SVG
```

4 倍那一版还在：`python3 通用模板/cast/hd/hd_base.py --scale 4`（要 onnxruntime + Real-ESRGAN 权重，产物 172 MB，**不入库**），引擎那边把 `motion_hd.mjs` 的 `S` 用 `HD_SCALE=4` 起一次、重烘图集即可。

## 还没做、没验证的

- **引擎接的细节层是这张图集**（`cast_hd_atlas.png`，6144×3878 / 682 格；SVG 不进成片）。
- 4 倍超分那条路（`--scale 4`）在这个环境里**没有真跑过**：装不上 onnxruntime、没有权重。表里 4 倍的数字都是 fix 包自报的，不是这里量的。
- 2 倍素材是「像素艺术放大」：形状和 1 倍完全一致，没有超分那种「模型推断出来的细节」。要更强的锐度得回到 4 倍超分那条路。
- 本鲸的走路帧比正面格偏暗偏灰，原素材就这样，没有校色。
- SVG 的观感只在 resvg 里抽查过（whale 第一格）；没有在浏览器里逐个打开过，也没有量过与 PNG 的像素差。
- `svg_pack.mjs` 把整位角色的基础格排成一列（105 格）；按动作表逐格切片的「拼动作」还没有接到引擎里——引擎走的是高清图集。
