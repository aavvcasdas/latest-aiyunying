# 新方案：资产能力契约 + 拍点事件分镜 + 分层纸片表演

## 一、推荐结论

**不用视频生成模型。图片模型负责经过审核的角色部件 / 姿态差分，代码负责确定性表演、镜头和合成。** 复用同一套图片能稳定外观，但不自动保证姿态正确、接触可信或分镜好看。

本仓库已具备代码出片基础。建议的主线不是“抛弃 Three.js，全部改成 Pillow”，而是：

1. 保留现行模板的 `align`、字体 / 素材校验与正式出片入口。
2. 增加角色包规范、动作能力声明、事件分镜与预检。
3. 做一个真正的双人互动镜头；需要柔性部件时，再给人物层引入 PixiJS Mesh 或自有 Canvas 网格模块，二选一，不同时装多套运行时。
4. Remotion 继续负责编排与导出；Three.js 仅保留给确实需要空间运镜的镜头。Python 用于资产加工、离线 QA 和轻量实验。

**不因框架热门而迁移；先用同镜 A/B 证明收益。**

## 二、用户提供的开源拼图如何用

以下是用户提供的候选方向，非本轮联网核实的版本 / 许可 / 可运行性结论：

| 候选 | 可借鉴 | 当前决策 |
|---|---|---|
| `facebookresearch/AnimatedDrawings` | 单图分割、关节点、网格与动作重定向 | 限定站姿测试集再试；不假定任意动漫图都能拆好，也不直接接入成片 |
| Remotion 与相关 Claude skills | 分镜到代码、合成与检查流程 | 本仓库已有 Remotion，优先复用，不重搭 |
| Motion Canvas / Revideo | 顺序式导演语法 | 借鉴事件语义，暂不迁移运行时 |
| PixiJS Mesh / Spine / Live2D、Rev2D | 部件、关节和网格动画 | 先做最小 mesh 原型；各自许可、格式和维护状态需单独验证，不能统称“全开源免费” |
| Blender Python | 真实空间、投影、复杂光照 | 仅用于确实需要的 2.5D 镜头，不作为默认批产路径 |
| Pillow / FFmpeg | 资产加工、静帧检查、无浏览器编码 | 本轮隔离实验；速度不代表复杂场景性能 |

用户提到的 `qunian-mv`、`actions-v12`、`lyric-action-v13`、`mv-kit` 等属于提供的背景线索，本轮没有在当前仓库确认这些入口；不会假定其已安装或照路径调用。实际可复用的是当前仓库的图集、模板、立绘横带代码与音频对齐工具。

## 三、四层架构

```text
经授权的图片资产 / 现有图集
    ↓ 人工审查、遮挡补画、alpha / 锚点 / 能力验收
角色包：PNG + 坐标、层级、允许动作、来源哈希
    ↓
导演 JSON：镜头 + 拍点事件 + 接触关系 + 歌词引用
    ↓ 预检：能力、时间、接触、素材、字形
确定性人物执行器 + 场景 / 相机 + 现行合成导出
```

### 3.1 资产层：先能演，再追求拆得多

默认继续复用现有 Q 版像素图，保留 NEAREST 采样和风格；不把高清立绘偷偷替换进去。

若后续明确授权新图或换画风，再准备：主姿态、两三个关键姿态、局部表情差分、独立道具。不是每个角色机械地生八张互不一致的零件。

真正需要独立运动的部件才拆：前臂 / 上臂、前后发、头、躯干、裙摆；连接处画出被遮挡的重叠区域。用参考图和局部编辑锁定外观，但**必须人工比对，一致性不是提示词的保证**。

角色包最少字段：

```json
{
  "id": "whale",
  "canvas": [1024, 1536],
  "style": "existing-pixel",
  "capabilities": ["idle", "step", "hop"],
  "parts": [{"id": "body", "image": "body.png", "pivot": [512, 1450], "z": 0}],
  "anchors": {"foot": [512, 1450]},
  "source_sha256": "由打包工具计算，不手填占位值"
}
```

上例是拟议格式，不是已可加载的当前角色包。坐标统一为原画布左上原点像素；每层保留裁切偏移，不能靠图片中心猜颈 / 肩位置。只有提供并审核了手部图层和手锚点，才能声明递物能力。

纯绿不总比透明底好：绿头发 / 透明饰品易被误抠，白底也可能误删白衣。优先可靠 alpha；色键只做可检查的备选。自动抠图、自动关节点、遮挡补画是不同步骤，不能把裁片工具叫“全自动拆件”。

### 3.2 导演层：从“第几秒缩放”改为“谁先做、谁接住”

拟议事件语法（尚未由本轮原型实现）：

```json
{
  "shot": "pass-flower",
  "start": {"beat": 8},
  "duration_beats": 4,
  "events": [
    {"at_beat": 0, "actor": "whale", "action": "anticipate_pass"},
    {"at_beat": 1, "prop": "flower", "action": "release", "from": "whale.handR"},
    {"at_beat": 2, "prop": "flower", "action": "catch", "to": "claude.handL"},
    {"at_beat": 2.25, "actor": "claude", "action": "react"}
  ]
}
```

事件拍号相对镜头，编译时映射到全片实测拍点；动作求值时统一使用全片时钟，避免第二镜重置时间后还查全曲拍点的错误。

预备 → 出手 → 接触 → 反应 → 恢复，是表演的核心。可用既有关键姿态切图，在重拍加适度遮挡 / 冲击效果；不必强求全部连续骨骼化。

### 3.3 表演层：按动作选择技术，不强行网格化

- 站立呼吸、踩拍：整图局部幅度的挤压拉伸；承认只是兜底。
- 抬臂、递物：有覆盖余量的独立部件 + 关节层级 + 手部锚点。
- 发梢 / 裙摆：少量网格控制点 + 可解析阻尼曲线；或从零重放的固定步长模拟。不能随播放顺序累积状态。
- 转身 / 大透视变化：经过审核的姿态差分，不把正面图横向压扁当成真正转身。
- 双人互动：道具释放 / 接触点绑定到手锚点；检查画面距离、层级和接触时刻；不能画假手来弥补缺资产。
- 沸腾线：真正轮廓扰动 / 少量线稿差分才接近 boiling line，整图随机抖动只是贴纸抖动。默认像素风不强行加水彩纸纹或乱抖。

### 3.4 时间与导出

正式 MV 继续使用模板生成的 `cues.json`，音源或歌词变化必须重新 `align`。检测到的 onset 不是已验证鼓点，BPM 网格更不能冒充实测。

字幕按真实歌词 / 词级时间戳；没有词级对齐就按句显示，不按镜头百分比伪造逐字卡点。只用模板 ZCOOL KuaiLe，缺字立即失败。

离线顺序、倒序和随机跳帧结果必须一致；源 alpha / 中间帧保持无损，最后才 H.264 编码。不以滤镜掩盖低清源图，也不承诺有损编码后像素完全不变。

## 四、实施顺序与验收门槛

| 阶段 | 做什么 | 过关条件 |
|---|---|---|
| P0（本轮隔离实验） | 现有像素角色、拍点分镜、完整图变换、无声编码 | 8 秒 / 240 帧、无裁断、跳帧一致、非法分镜和有声输出被拒绝 |
| P1（建议下一步） | 一个角色包 + 两个角色的递花事件 + 接触检查 | 资产能力不足时报错；递出 / 接住的手和道具位置对得上 |
| P2 | 经授权的必要部件或姿态差分、mesh / 关节小样 | 接缝、遮挡、人物身份通过静帧与逐镜检查 |
| P3 | 接现行实测 cues，同一个八秒镜头做旧 / 新 A/B | 同资产、分辨率、帧率、音轨、编码与机器；记录耗时、峰值内存、接触误差和人工偏好 |
| P4 | 一个完整 MV 验证 | 音画、字体、素材检查 + 人完整看过听过；达标后再讨论迁移 |

不自动冻结旧引擎，不一次迁移二十部作品。没有同镜对照前，不声称提升几倍速度或画质。

## 五、本轮到底交付了什么

- `engine/rig.py`：完整像素贴图的待机 / 踩拍 / 跳跃 / 摇摆，**没有**独立头手、骨骼层级或 mesh。
- `engine/storyboard.py`：小范围无声分镜校验，要求连续镜头和明确结束拍。
- `engine/render.py`：确定性静帧与 RGB 管道编码；正式有声输出被拒绝。提供模板字体缺字校验接口，但无声片没有歌词。
- `engine/beat.py`：实验性 onset 候选提取，明确 `measured=false`，不进入正式音频链。
- `tools/split_parts.py`：水平裁片与坐标清单，不自动抠像、补画或绑骨。
- `tools/make_demo.py`：现有本鲸像素图的八秒无声样片；无新生图、无口型、无双人接触、无正式卡点声明。

**这证明了技术兜底能跑，不证明最终表演问题已经解决。下一笔投入应该放在一个可信的互动镜头，而不是再多搭一套空引擎。**
