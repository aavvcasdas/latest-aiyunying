# 当前项目诊断（2026-11-26）

## 结论

**不必再换一套大型引擎，也不应把旧项目全扔掉。先把“角色能演什么”和“分镜如何验收”做成契约。**

本仓库已经是“图片资产 + 代码渲染”的路线，问题不是没有用视频模型，也不是 Remotion 天生不好，而是资产能力、分镜需求与制作流程没有稳定对齐。

本轮只新增隔离实验与文档；不改现行模板、不重画角色、不改既有作品、不冻结旧引擎。

## 二、真正要解决的四个问题

### 1. 分镜要求超出资产能力

整张 PNG 无法凭变形变出被遮住的手、衣服背面和侧脸。粗暴水平裁成头身腿，会把长发和裙摆一起切断。它不是自动解剖分割，更不是骨骼绑定。

**改法：**每个角色包声明能力：能否抬臂、眨眼、转侧面、接道具。分镜调用不存在的能力直接报错，不拿整体摇晃冒充挥手。

### 2. 同拍动作不等于互动

两个人同时蹦不是递物。一段递物需要：发送者预备、手部锚点移动、道具脱手、飞行、接收者接住、余振恢复。镜头应该描述可验证的事件和接触关系，而不是只写缩放和平移。

**改法：**用拍点驱动事件图、动作预备与反应延迟；动作本体仍可复用现有逐帧图集。

### 3. 分镜与执行代码耦合

现有时间轴值得保留，但复杂镜头仍可能把表演、机位、字幕和场景构建写在一起。每次新 MV 再复制一套，公共修正很难传播。

**改法：**先为一个双人镜头建立 JSON 中间表示与唯一动作执行器，不一口气迁移全部旧片。特殊效果保留代码扩展点。

### 4. 缺少小步验证闭环

整片渲染太晚才暴露断层、越框、接物穿帮和字体缺字，修改成本高。

**改法：**先看关键姿态静帧，再看一镜六帧，再出八秒片，最后才整曲。机器检查和人眼 / 人耳验收分开记录。

## 三、留什么、延后什么

- **保留：**现行 `align` / `full`、确定性逐帧契约、Q 版图集、动作 / 道具、字体预检、缺素材即失败、现有成片和模板。
- **优先新增：**角色能力清单、锚点坐标规范、拍点事件分镜、互动接触检查。
- **经授权再做：**生图拆件、遮挡补画、风格迁移；默认仍是现有 Q 版像素资产。长大立绘仍只用于规定用途。
- **不立即做：**全仓换引擎、冻结旧作品、接入八套视频栈、承诺“一张图全自动复杂演戏”。

## 四、本轮实验揭示的边界

最初横带试片出现接缝、字体缺字和片头落错镜头；按 BPM 吸附也不能证明真实卡点。该试片已撤下，不作为交付依据。

修订后的实验只验证完整像素贴图的拍点压缩、连续跳跃、摇摆、无浏览器编码与跳帧确定性。它仍然是**整图变换兜底**，不是用户最终要的分层表演；不能据此宣称已经解决“立牌晃动感”。具体实测与未实现项见 `README.md` 和 `demo/qa.json`。
