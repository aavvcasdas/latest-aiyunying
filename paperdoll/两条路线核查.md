# 最新修订：Cutout + Iki 是组合，不再二选一（2026-11-26）

下面旧报告保留作为调研与失败记录。用户随后明确否定了混合蒙皮的橡皮手脚和 A2 肤色，并要求同一角色合用两种执行器；旧 8 部件 / 双路线 / 软蒙皮描述不是当前实现。

当前入口见 [README](README.md)。核心变化：

1. Cutout 每条肢体拆成 upper / lower 两张刚性纹理，使用肩肘 / 髋膝层级旋转，不做跨骨段混合。圆形重叠遮住转轴缝。当前正面姿态保留脚底固定，没有把侧折膝盖当走路。
2. 新生成无眼无嘴底图 v2，局部安装皮肤；非修补脸颊与鼻梁保留原像素。肤色对照鼻梁中性区域，不能取眼下腮红。原闭嘴线从底图移除，再由独立嘴层控制。
3. 真正 Iki 模型只保留眼睛 / 张闭嘴 / 闭眼线 6 部件，身体、脸底、四肢由 Cutout 画。Iki 透明结果在相同 912×1136 坐标合成进同一输出，不是并排演示。
4. 新增模板 whale_cutout，包含真实透明 eyes / mouth / hands。drawTachie 新的层绘制路径将各层只画一次、挂接到积分脊柱对应高度。基础层 API 支持独立透明度 / 刚性旋转；它本身不运行 Iki，也不冒称手指或左右臂 IK。浏览器预载会等待所有声明的图层，缺层报错。
5. 禁生图与不可更新哈希政策已解除。默认检查只提醒有意版本变动，--strict 才校验记录版本；缺文件和实时母版 / 镜像损坏仍报错。注册表能自动发现新增角色素材并记录版本，不再只列八位。

验证：先产出组合六格，再完整导出 240 帧并逐帧独立解码；26 项实验 Python、10 项刚性运动测试；模板分层单元测试、类型检查、9 角色锚点检查；《童话镇》L01 六格 / 全片 4272 帧前后序预检与 188 字字形检查。另用临时模板项目实测新分层 key 的预载、独立眼 / 嘴透明度和 hands 旋转，120 帧前后序一致、六格成功（该临时测试隐藏眼层仅为证实层独立，不是自然闭眼动作）。人工整片签收仍为 false。

## 二、实际重做了什么

### A：肢体 Cutout / 两骨骼蒙皮

1. 保留上轮用户选定的形象原图，不重新发明角色。
2. 图片模型补画“去除双臂后露出的头发与衣服”，生成 body cleanplate。模型在脸 / 胸前的非必要改动不接入 A；只用手臂原来遮挡的局部区域。
3. **人工标注**双臂、双腿多边形与肩 / 肘 / 手、髋 / 膝 / 脚坐标，写入 `assets/cutout/rig.json`。这不是自动分割或自动关节点识别。
4. 从原图取出真实的手臂与腿纹理，独立 alpha 层；没有画假手、没有在原位置留原手。
5. 前向运动学计算上臂和前臂，肘部附近用连续权重混合；腿同理。WebGL2 一次绘制共享边的纹理三角形，避免 Canvas 逐三角 clip 产生细网格接缝。
6. 八秒示范：抬肩 → 屈肘 → 挥手 → 放下 → 另一侧伸臂 → 髋膝踏步。身体根节点不位移、不缩放、不旋转。

**边界：**仍是手工切件与原画纹理的有限变形。没有新增手掌方向差分，没有 IK 脚底锁定，没有复杂遮挡排序或碰撞。踏步是关节小样，不是已验收的自然行走；袖子在极端屈肘时仍可能压缩，不宜直接用作正式 MV。

### A2：实际 Iki 自动绑定 / 面部参数

1. 图片模型补出无眼无嘴的面部底层，保留头发与脸型；局部肤色匹配。
2. 原图眼睛独立取层，剔除残留肤色与孤立高光；闭嘴 / 张嘴、闭眼线为明确的独立绘制层，不宣称模型自动推断隐藏画面。
3. Python 从每层 alpha 实测 bbox / row runs，再交给 `generateIkiFromLayerSet`；绑定结果由 `parseIkiModel` 校验。
4. 将纹理和生成的变形网格打包到 `whale.iki`；使用真正的 `IkiPlayer` 播放。
5. 自动表情测试只驱动 `ParamEyeLOpen` / `ParamEyeROpen` / `ParamMouthOpenY`；页面提供眼睛与嘴部开合滑块。
6. 图片作者还显式补上两条闭眼线图层，以免眼网格完全折叠时出现无眼脸；这是绑定后的人工增强，不是 Iki 自动分层的成果。

**边界：**没有音轨，嘴部只是参数测试，不是 Rhubarb / Whisper 对齐口型。未制作真正的虹膜独立层、侧脸或头发分层，所以未启用头部摆动与发丝物理；自动绑定虽然声明了头部参数，并不等于当前图层足以支撑好看的大角度转头。没有导出 `.moc3`。

## 四、复现

先按根 README 配好 Python 依赖与根 Node 依赖。然后在仓库根执行：

```bash
npm ci
npm ci --prefix paperdoll/runtime
python3 paperdoll/tools/prepare_cutout.py
python3 paperdoll/tools/prepare_iki.py
npm run model --prefix paperdoll/runtime
npm run bundle --prefix paperdoll/runtime
npm test --prefix paperdoll/runtime
python3 -m unittest discover -s paperdoll/tests -v
```

启动预览（这条命令持续运行）：

```bash
python3 -m http.server 8000 --bind 0.0.0.0 --directory paperdoll
```

另开终端，浏览器交互检查：

```bash
node paperdoll/tools/render_puppets.mjs --check
```

导出两段样片：

```bash
node paperdoll/tools/render_puppets.mjs
```

软件 WebGL 渲染整组可能需要数分钟，给命令足够时间；中间 PNG 与临时 Chromium 库都在系统临时目录，不进 Git。首次整体导出在平台 180 秒限制处中断，已复用临时帧补完 B 的剩余部分，最终分别重新完整解码确认 240 帧。本轮没有把缺帧补帧或拉长视频来凑时长。

若只看已有静态页面，预览服务器无需安装或下载模型，也不依赖 CDN。浏览器必须支持 WebGL2，缺素材 / 纹理失败会显示错误而非替换角色。

## 五、验收记录与判断

- B 的闭眼 / 张嘴改变图像；随机跳帧一致；滑块写入的运行时参数确为眼睛零开度、嘴部全开度。

- 两段各 8 秒 / 240 帧 / 1280×720 / 30 fps / H.264 / 无音轨，完整解码检查通过。
- 已抽看挥手、踏步、睁眼、闭眼、张嘴静帧；**无人完整观看签收，不把机器通过说成动画好看**。

**建议：全身分镜互动以 A 为主，近景表情以 A2 为辅。** 两者不是互相取代：肩肘解决“手真的动了”，面部参数解决“会眨眼张嘴”。下一步应补少量关键手掌 / 接物姿态与必要遮挡层，再对一个真实互动镜头做验收，而不是重新加整图晃动。
