# 通用模板做 MV 的流程

事实依据只有三处：`通用模板/README.md`（用法与规矩）、`AGENTS.md`（交付与红线）、`设定/README.md`（人物设定，一人一页）。
这个仓库**只做 MV**：Day 口播线、存档、运营文档都已经删除，文档里见到 `Day/…`、`存档/…` 这类路径是历史记录，不要照着找。

## 0. 开工前

写镜头或派角色之前，先读那个人那一页（`设定/人物/`）：她先做什么、关心落在哪件小事、能演什么形象、哪些话不许说。
设定里没有的角色不要写进镜头。每支新 MV 先填 `番外MV/设定表.md` 第 5 节那张空表（她在这支里是谁、兑现哪条习性、一个能拍出来的动作、不许写成）。

```bash
npm ci && pip install --user numpy pillow      # 没装过才需要
npm run film -- info 番外MV/童话镇               # 确认作品能加载、看时间轴
node tools/render_zip_mv.mjs fable --still 30   # 《坏女孩》两版走这条出片脚本
```

`info` 最后一行会说「仓库里的成片是不是现在这份源码渲的」。不一致就意味着成片已经过期。
`info` 还会做一遍**角色预检**（不出图，把全片每一帧走一遍）：哪个镜头点了图集里没有的格子、哪个角色的坐标算成了 NaN、哪个角色的样子取决于之前渲过哪些帧。没通过就先修，不要加 `--allow-cast-problems` 硬渲。
同一趟里还有**文字预检**：字幕、字卡、镜头画在 Canvas 上的字，逐字和模板字体核对。字体里没有的字（`→ ★ ♪ ①` 这类符号、生僻字）成片里是豆腐块，而渲染照样报成功。没通过就改字，不要加 `--allow-missing-glyphs` 硬渲。

## 1. 判断是哪种活

| 用户要的 | 走哪条 |
|---|---|
| 新一部 MV | `npm run new -- mv 番外MV/歌名 "歌名"` → 第 2 节 |
| 改已有作品的镜头 / 歌词 | 直接改作品目录里的 `shots/`、`歌词.srt`、`project.tsx`；改了歌词要重跑 `plan`（没有音源）或 `align`（有音源），不重跑其他命令会拒绝干活 |
| 原曲到位了 | `align` → `full` |
| 改《坏女孩》两版（自带引擎，不走模板） | 改 `番外MV/坏女孩/src/`、`番外MV/坏女孩Fable/api/`，出片 `node tools/render_zip_mv.mjs three3d\|fable` |
| 引擎缺功能（新道具、新造型、新字幕样式） | 改 `通用模板/engine/`，然后 `npm test && npm run typecheck`，并对 `番外MV/童话镇` 跑一次 `sheet` |

## 2. MV

1. 原曲放 `素材/`，`film.json` 加 `audio`；换 `歌词.srt`（**一句一行，句子要和唱的一致**，别把一句唱词从中间劈开）。
2. `npm run film -- align <目录>`：实测拍点、歌词起点吸附到实拍。看输出里的「平均移动 / 最大移动」，最大移动接近半拍说明歌词时间本身不准。
3. 排镜：一句一镜为主，长句中间再切；**前奏 / 间奏 / 尾声没有歌词的地方最容易被写成一个大长镜**，那里要按拍点切成多个分镜（《坏女孩》fable 版间奏 32 秒里切了 13 个镜头，可以直接照）。
4. 写镜头：动作卡 `bt.pulse` / `bt.idx`；重拍 `bt.down`。
5. `sheet` → 改 → `full`。

## 3. 出成片

```bash
npm run film -- align <目录>     # 换了音源必须重跑
npm run film -- full <目录>      # frames → encode → mux → qa → sheet
node tools/render_zip_mv.mjs fable    # 自带引擎那两版
```

- `full` 开头就会检查：音源在不在、卡点是不是按当前音源实测的、音轨解不解得出来。任何一项不行就直接停。
- 看 `成片/qa.json`：`frames.problems`、`timing.problems`、`final.problems` 都应为空；`final.audio_lag_vs_source_samples` 应为 0。
- `npm run film -- strip <目录>`：整片每秒抽一格拼成胶片条，**每一张都要看**——有没有哪一秒人不见了、道具跳位、字幕不对。
- 成片 >100 MB 推不上 GitHub：调低 `film.json` 的 `video.bitrate`。

## 4. 写镜头时最容易犯的错

- 在逐帧函数里用了 `Math.random()` / 累加变量 → 跳帧渲染和连续渲染结果不同。用 `hash(n)`。
- `track([[0, A], [0.5, B], [1, B]])` 后半段两个关键帧一样 → 镜头冻住，qa 报「画面冻住」。
- `track` 的关键帧时间没按从小到大写 → 直接报错。
- 人被画框切掉半个、一停好几秒。要么完整入画，要么完全在画外。
- 平放在桌上的纸从正面机位看是一条线 → 俯拍，或者 `standing()` 立起来。
- 雨丝下到镜头跟前 → 一条粗白杠。把 `rain()` 的纵深限制在人物那一段。
- 同一场景的连续镜头各摆各的 → 一切镜道具跳位。摆位写成常量共用。
- 角色或道具只在一部分帧里写了状态 → 没写的帧停在「上一次渲到的样子」，成片里隔帧乱跳。每一帧都写全。`info` 的预检会报出来。
- 忘了 `.flip()`：两人对谈时右边的人要翻转才面朝左。
- 人物贴着画面底边 → 被字幕条挡住。
- 造型名写错 → `set()` 抛错（这是对的，别 try/catch 掉）。
- 往 Canvas 上画字时字体写成 `sans-serif` → 每台机器画出来不一样。一律用 `@tpl/fonts` 的 `FONT` 或 `writeLine()`。
- 歌词条与唱词对不上：多半是拿「等距网格」硬排时间（第 k 句 = 起点 + k×固定间隔）。句子间距在歌里从来不等距，必须逐句实测。

参考作品：MV 看 `番外MV/童话镇/`（模板线）和 `番外MV/坏女孩Fable/`（自带 Canvas2D 引擎、逐句实测卡点、间奏多分镜）。

## 5. 汇报

分开写三件事：

1. **机器查过的**：qa.json 的结论、帧数、时长、音画偏移、文件大小与 SHA256。
2. **我看过的**：看了哪些静帧 / 总览图 / 胶片条，发现并改了什么。静帧看不出动作顺不顺，别写成「看过整片」。
3. **没人做过的**：整片连续观看、听审。没做就写没做。

然后提交、推送到当前会话分支，给出真实提交号。提交前跑 `npm test`：除了引擎的测试，它还核对现行文档里的命令、选项、路径是不是都还在。

## 红线（违反即返工）

零水印零角标；不出现粉丝数 / 播放量 / 进度条 / 数据图表 / 账本表格；不画假手；不新增生图；缺素材不许回退；`measured=false` 的东西不许叫成片。
